Project 12: Process Comparison Analysis

Tujuan project: membangun analisis statistik dan dashboard yang membandingkan kekuatan glue pada proses camera cover glass bonding antar kondisi proses (sebelum oven, setelah oven, setelah baked) dan antar model (Model A dan Model B), untuk mengetahui perbedaan mana yang nyata dan seberapa besar risikonya terhadap batas spesifikasi, sehingga kondisi proses terbaik dapat dipilih berdasarkan bukti.

Kategori:Rancangan projectManufaktur smartphoneData simulasiStatistik + dashboard

Project Introduction

Bayangkan Anda menempel gantungan di dinding dengan lem. Ada yang langsung dipakai, ada yang ditunggu sampai lemnya kering, dan ada yang dijemur di bawah lampu panas agar lebih cepat mengeras. Untuk menguji, beberapa gantungan ditarik sampai lepas sambil dicatat berapa beban yang ditahan.

Anda ingin tahu tiga hal: apakah menunggu lem kering benar membuat gantungan lebih kuat, apakah dua merek gantungan berbeda kekuatannya, dan seberapa besar kemungkinan sebuah gantungan lepas di bawah beban minimum. Satu kali tarik tidak cukup untuk menjawab. Perlu cukup banyak sampel dan cara membandingkan yang adil.

Project ini membangun analisis perbandingan proses dan dashboard: data push test dari mesin dirapikan, dimasukkan ke satu database, dibandingkan antar kondisi dan model dengan uji statistik, lalu ditampilkan dalam dashboard. Datanya adalah data simulasi yang meniru format file mesin push test, karena data asli hanya menyimpan ringkasan per sesi. Kata bergaris bawah putus-putus kuning bisa diklik untuk melihat artinya.

Gambaran alur kerja di proses camera cover glass bonding

Proses dan pengujian bisa dibayangkan sebagai tiga jalur. Dua jalur pertama sudah berjalan di lini. Jalur ketiga adalah yang dibangun di project ini.

  1. Jalur proses. Glue dioleskan, cover glass dipasang, glue dikeraskan dengan UV, lalu dipanaskan di oven. Seperti gantungan yang ditempel lalu dibiarkan kering.
  2. Sampel diuji. Beberapa cover glass dari setiap kondisi diuji dengan push test sampai lepas. Gaya saat lepas menunjukkan kekuatan glue.
  3. Jalur pengujian. Project membandingkan kondisi proses dan model, termasuk sebaran gaya, karena cover glass dengan gaya di bawah 2.000 g dianggap NG.
  4. Jalur data. File CSV dari mesin dirapikan, dimasukkan ke database, diuji secara statistik, lalu ditampilkan di dashboard. Hasilnya dipakai untuk memilih kondisi proses terbaik.

1. BackgroundKenapa tema ini dipilih

Latar belakang masalah

Pada proses camera cover glass bonding, kekuatan glue diuji dengan push test destruktif. Mesin menyimpan hasil setiap sesi dalam file CSV terpisah, dengan baris ringkasan di atas dan angka berformat koma desimal. Data lalu dikumpulkan dengan macro Excel. Akibatnya:

  • Keputusan proses diambil dari rata-rata satu atau dua sesi, tanpa uji apakah perbedaannya nyata.
  • Efek oven dan perbedaan antar model tercampur, sehingga sulit tahu mana yang sebenarnya berpengaruh.
  • Sebaran gaya jarang diperhatikan, padahal sesi dengan rata-rata tinggi pun bisa punya unit di bawah batas 2.000 g.
  • Format file yang tidak konsisten (nama file, label kondisi, koma desimal) membuat penggabungan data lama dan rawan salah.

Alasan memilih tema ini sebagai portofolio

  • Dekat dengan pengalaman kerja. Data push test hasil perekatan pernah diolah langsung dengan macro VBA, sehingga konteks dan masalah formatnya dipahami.
  • Menunjukkan skill inti Data Analyst. Parsing data mesin, uji t dan ANOVA, effect size, confidence interval, kapabilitas proses (Cpk), dan menerjemahkan hasil statistik menjadi rekomendasi proses.
  • Tingkat kesulitan mudah. Uji statistiknya standar, dengan jumlah kelompok yang sedikit (2 model × 3 kondisi).
  • Terhubung dengan project lain. Pipeline file mesin dibangun penuh di Push Test Data Pipeline (#20), pemantauan berkala di SPC Control Chart (#15), dan cara menguji perbedaan sama dengan A/B Test Analysis (#11).

4. DatasetData simulasi yang meniru format file mesin push test

Kenapa data simulasi? File push test asli hanya menyimpan satu baris detail per file beserta ringkasan sesi: gaya maksimum, minimum, rata-rata, Cpk, dan jumlah fail. Data per cover glass tidak lengkap, jadi uji statistik per unit tidak bisa dilakukan. Data simulasi dibuat dengan program Python yang meniru format file mesin dan kisaran angka sesi asli, lalu kejadian khusus ditanam agar hasil analisis bisa diperiksa.

Ukuran: 2 model, 3 kondisi, sekitar 60 sesi uji dengan sekitar 10 cover glass per sesi, atau sekitar 600 hasil push test selama ±3 bulan. Jumlah pastinya baru diketahui setelah data dibuat. Ringkasan sesi asli dipakai sebagai pembanding kisaran angka.

Fakta yang sengaja ditanam (ground truth)

1. Gaya lepas setelah oven dibuat rata-rata sekitar 10% lebih tinggi daripada sebelum oven.

2. Model Model B dibuat sekitar 5% lebih lemah daripada Model A pada kondisi yang sama.

3. Efek oven dibuat lebih besar pada Model B daripada Model A (ada interaksi).

4. Satu sesi dibuat dengan sebaran sangat besar dan 2 cover glass di bawah 2.000 g, mirip salah satu sesi asli.

5. Sekitar 2–3% data kotor disisipkan: koma desimal, label kondisi kosong atau tidak konsisten di nama file, gaya nol, dan baris ganda.

Empat tabel yang akan dibuat

File mesin berisi ringkasan sesi dan detail per cover glass dalam satu file. Data dipisah menjadi beberapa tabel yang terhubung lewat kode sesi, seperti beberapa sheet Excel yang dihubungkan dengan satu kolom kunci. Dengan begitu ringkasan dari mesin bisa dicocokkan dengan hitungan ulang dari data per cover glass.

5. ToolsAlat yang dipakai dan alasannya

Python (pandas, SciPy, statsmodels)

Membuat data simulasi, membaca file CSV mesin, dan menjalankan uji t, ANOVA, uji Tukey, uji Levene, effect size, dan Cpk. Satu skrip bisa dijalankan ulang kapan saja.

Sesuai kolom Tools di daftar portofolio (SciPy, pandas). statsmodels menyediakan ANOVA dua arah dan uji Tukey.

DuckDB + SQL

Database tempat semua tabel disimpan. SQL dipakai untuk ringkasan per kombinasi, fail rate, dan pencocokan ringkasan mesin dengan hitungan ulang. Perhitungan dibuat sebagai view.

Gratis, tanpa server, cukup satu file. Konsisten dengan project lain di portofolio.

Jupyter Notebook

Mencatat langkah analisis statistik beserta grafik dan penjelasan, sehingga pembaca teknis bisa mengikuti alasan setiap uji.

Sesuai kolom Tools di daftar portofolio, dan format yang umum dibaca reviewer data.

Streamlit + Plotly

Membuat dashboard web dengan box plot per kombinasi, hasil uji, Cpk, dan simulasi sebaran gaya. Dipublikasikan gratis di Streamlit Community Cloud.

Ditambahkan di luar daftar portofolio agar hasil bisa dibaca engineer dan supervisor tanpa membuka notebook.

GitHub

Menyimpan kode, contoh file mesin hasil simulasi, dan README. Recruiter melihat project langsung dari repositori.

Standar industri untuk portofolio dan riwayat perubahan kode.

Markdown

Menulis README: masalah, data, analisis, rekomendasi, dampak, dan batasan.

Format teks sederhana yang tampil rapi otomatis di GitHub.

9. Assumptions & LimitationsKomponen tambahanKeputusan yang sudah diambil dan hal yang perlu diwaspadai

Jenis data: simulasi meniru data push test Sudah Anda setujui

Format file dan spesifikasi mengikuti file mesin asli, tetapi data per cover glass dibuat dengan program. Hasil akhir membuktikan bahwa metode bekerja, bukan menggambarkan proses sebenarnya.

Tools: DuckDB + SQL + SciPy + Streamlit Sudah Anda setujui

SciPy, pandas, dan Jupyter sesuai daftar portofolio. DuckDB dan Streamlit ditambahkan agar konsisten dengan project lain; kolom Tools di daftar sebaiknya diperbarui.

Konteks: camera cover glass bonding, Model A dan Model B Sudah Anda setujui

Halaman memakai konteks perekatan camera cover glass pada smartphone. Nama produk dan proses disamarkan dari konteks kerja asli.

Aturan uji dan angka asumsi Usulan awal

Alpha 0,05. Selisih minimum yang dianggap bermakna secara praktis 500 g. Cpk dihitung satu sisi terhadap batas bawah 2.000 g dengan target minimal 1,33. Estimasi NG memakai asumsi sebaran normal, dan dicek ulang dengan fail rate aktual. Jika sebaran jelas tidak normal, uji non-parametrik dipakai.

Hal yang perlu diwaspadai Usulan awal

Sampel per sesi kecil. Sekitar 10 cover glass per sesi membuat hasil satu sesi mudah naik-turun. Perbandingan dilakukan per kombinasi, bukan per sesi.

Pola belum tentu penyebab. Jika kondisi setelah oven lebih kuat, bisa juga karena sesi diuji di hari berbeda dengan lot glue berbeda. Penyebab perlu dicek di lapangan.

Uji destruktif. Cover glass yang diuji rusak, sehingga jumlah sampel terbatas. Kesimpulan dibaca bersama confidence interval.

Efek oven terbukti: gaya setelah oven 1 jam rata-rata 747 g lebih tinggi dibanding sebelum oven, dan selisih ini di atas batas praktis 500 g. Setelah baked tidak berbeda dengan setelah oven 1 jam. Estimasi (label estimated): penurunan fail rate estimasi 5,64 ppm untuk Model A dan 0,034 ppm untuk Model B per 1 juta unit. Angka ini kecil karena kedua model sudah memenuhi Cpk 1,33 sebelum oven. Nilai praktis utamanya adalah margin median 551 g dan 847 g.

7.4 Rekomendasi

Gunakan setelah oven 1 jam untuk kedua model sebagai kondisi proses default, dengan verifikasi pada data lini nyata. Selidiki sesi S037 dan lot glue-nya sebelum menyimpulkan tentang variasi sebelum oven.

7.5 Saran perbaikan

  • Hitung daya setiap fakta sebelum membuat data simulasi, agar efek kecil tidak diuji tanpa daya.
  • Tambahkan jumlah sesi per kombinasi, karena uji per unit dengan sesi terbatas mudah terlalu percaya diri.
  • Catat lot glue per sesi agar pola yang terlihat bisa dipisahkan dari hari atau lot.
  • Publikasikan dashboard, lalu minta pembaca awam menguji dashboard.

7.6 Batasan

  • Data adalah simulasi. Angka menggambarkan data buatan, bukan lini produksi.
  • Fakta interaksi tidak terdeteksi. Daya deteksi hanya ±554 g, sedangkan selisih yang ditanam 624 g. Ini kesalahan perancangan, karena daya tidak dihitung sebelum data dibuat.
  • Sesi S037 sangat menyebar dan menentukan semua NG. Kapabilitas Model A sebelum oven sensitif terhadap sesi ini (lihat tabel sensitivitas).
  • Unit bersarang dalam sesi. Uji per unit bisa terlalu percaya diri, sehingga uji per sesi dilaporkan sebagai pembanding.
  • Residual tidak normal (Shapiro-Wilk). Welch dan Mann-Whitney dilaporkan bersama.
  • Asumsi: batas praktis 500 g, target Cpk 1,33, estimasi ppm dengan sebaran normal, koreksi Bonferroni. Semuanya diuji sensitivitasnya.
  • NG hanya 2 kejadian, sehingga fail rate dan ppm tidak stabil.
  • Dashboard belum dipublikasikan. Repositori belum digabung ke main.
  • Pola yang terlihat belum tentu penyebab. Sesi yang berbeda bisa berbeda lot glue atau hari.
